# Argus v1 — a small AI SaaS whose first client is Lovixa

## Context

Argus (`lg/qrapps-argus`) is a parked TypeScript monorepo (Fastify API + Next dashboard, 24k lines, zero tests,
dormant since 2026-07-11) that went through four product visions. The owner now wants to rebuild it as a
**simple AI SaaS** and be its first customer: log in, create a company (Lovixa), link Facebook, let the AI
propose one default objective ("see the market on Facebook"), confirm it, and have Argus collect data,
discard noise, keep real values and report back.

Decisions already taken with the owner (2026-11-03):
- **Stack**: fresh Next.js + Supabase (Auth, Postgres with RLS), same stack as Lovixa so patterns transfer.
- **Facebook scope**: own pages **and** public competitor pages. Public pages are reached through Meta's
  official **Page Public Content Access** feature, which needs Meta App Review. **No scraping**: it violates
  Meta's terms and would get the app and the Lovixa page banned. Until review is granted, v1 collects from the
  owner's own pages and the public **Meta Ad Library API** (no review needed).
- **Location**: same repo, new `apps/argus` folder. Old code deleted on the owner's request (git history keeps it).
- Postgres: a **new Supabase project** created by the owner, ref `easwymowinwctfalklux` (keys in `.env.local`, never in git).
- **Unverified**: whether the Ad Library returns commercial ads for Tunisia. Outside the EU it may return only political and
  issue ads, which would leave the own page as the only source before App Review. First thing to test after the migration.

## What v1 is (and is not)

v1 = one loop: **sign in → company → connect Facebook → objective proposed by AI → confirm → collect → filter → report**.
Not in v1: billing, teams/invites, other channels, chat-with-data, automations, the old knowledge layer.
The schema has `company_id` on every row and RLS from day one so a second customer is a sign-up, not a rewrite.

## Architecture

```
apps/argus (Next 16, React 19, App Router, Tailwind 4, zod 4, @supabase/ssr)
  ├─ app/(auth)/login, /signup           Supabase Auth (email + password)
  ├─ app/companies/new, /c/[slug]        company home: objective card, sources, reports
  ├─ app/c/[slug]/sources                connect Facebook (Meta OAuth), list pages, add competitor pages
  ├─ app/c/[slug]/objectives             AI-proposed objective, confirm / edit
  ├─ app/c/[slug]/reports/[id]           report with evidence rows
  ├─ app/api/meta/callback               OAuth code → long-lived token (encrypted at rest)
  ├─ app/api/jobs/run                    cron-triggered (Vercel Cron) job runner, service role, server only
  └─ lib/
     ├─ supabase/{server,client}.ts      SSR client per Lovixa pattern
     ├─ meta/graph.ts                    Graph API client: me/accounts, {page}/posts, comments, insights,
     │                                   ads_archive (Ad Library), rate-limit aware
     ├─ ai/gemini.ts                     structured-output calls (thinkingBudget=0 gotcha from CLAUDE.md)
     ├─ ai/propose-objective.ts          company profile → one default objective (JSON, zod-validated)
     ├─ ai/filter-signals.ts             raw items → keep/discard + extracted values, with reason
     ├─ ai/write-report.ts               signals → report; every number must map to a signal id (critic check)
     └─ crypto.ts                        AES-256-GCM, ported from legacy apps/api/src/llm/secret.ts
supabase/ (new, for Argus)  migrations/, RLS, pgTAP optional later
```

Jobs run inside Next (route handler hit by Vercel Cron every 15 min; locally via `curl`). No BullMQ, no Redis,
no worker process. If collection ever exceeds a function timeout, move the runner to a Supabase Edge Function.

## Data model (migration 0001)

| Table | Purpose | Key columns |
|---|---|---|
| `companies` | tenant | id, owner_id (auth.users), name, slug, description, market (country/city), created_at |
| `company_members` | RLS anchor (owner only in v1) | company_id, user_id, role |
| `connections` | linked external accounts | company_id, provider (`meta`), external_user_id, token_ct, token_iv, expires_at, scopes[] |
| `sources` | things to collect from | company_id, connection_id (null for public), kind (`own_page`, `public_page`, `ad_library_query`), external_id, name, config jsonb, status (`active`,`pending_review`,`error`) |
| `objectives` | what the AI proposed and the owner confirmed | company_id, title, description, target_kind (`market_watch` default), source_ids[], filters jsonb, status (`proposed`,`confirmed`,`paused`), proposed_by (`ai`,`user`), confirmed_at |
| `collection_runs` | one execution of an objective | objective_id, started_at, finished_at, status, items_seen, items_kept, cost_usd, error |
| `raw_items` | what the API returned, 30-day retention | run_id, source_id, external_id (unique per source), kind (`post`,`comment`,`ad`,`insight`), payload jsonb, fetched_at |
| `signals` | kept values after the AI filter | company_id, objective_id, raw_item_id, kind, value jsonb (numbers, entities, quotes), importance (1-5), reason, created_at |
| `reports` | written output | company_id, objective_id, run_id, period, body_md, evidence jsonb (signal ids per claim), status (`draft`,`verified`,`failed`) |

RLS: every table filtered through `company_members`. Service role used only by the job runner. Tokens never
leave the server; `token_ct/iv` follow the legacy Argus column pattern.

## The product loop in detail

1. **Sign up / log in** → `/companies/new` → company row + owner membership (one transaction via RPC).
2. **Connect Facebook**: Meta Login with `pages_show_list, pages_read_engagement, pages_read_user_content,
   read_insights, ads_read`. Store the long-lived user token encrypted; list pages from `me/accounts` → create
   `own_page` sources. Competitor pages: owner pastes a page URL → `public_page` source with
   `status='pending_review'` until the app has Page Public Content Access; Ad Library queries (`ad_library_query`
   with search terms + country TN) work immediately.
3. **Objective**: on company creation, `propose-objective` reads the company profile + sources and emits ONE
   default objective (title, what to watch, which sources, which signal kinds, cadence). Shown as a card:
   *Confirm* / *Edit* / *Something else*. Nothing runs before confirmation.
4. **Collect** (cron): for each confirmed objective, fetch new items per source since the last cursor, store in
   `raw_items` (idempotent on `(source_id, external_id)`), respect Graph rate limits (back off on 4/17/32 codes).
5. **Filter**: batch raw items to Gemini with the objective; output per item `{keep, importance, kind, value, reason}`.
   Deterministic pre-filter first (dedupe, language, empty text) so the LLM sees less. Kept rows → `signals`.
6. **Report**: weekly (and on demand) `write-report` turns the period's signals into a short Markdown report
   with a claims→signal-ids map. A **critic pass** re-checks every number against its signal; mismatches fail the
   report (status `failed`) instead of publishing. Owner reads it at `/c/lovixa/reports/[id]`.

## Phases (each ends with a check you can run)

| # | Phase | Deliverable | Done when |
|---|---|---|---|
| 0 | Owner prep | New Supabase project; Meta developer app (Facebook Login + Marketing API products); `.env.local` filled | `supabase link` works; Meta app id exists |
| 1 | Scaffold + auth + company | `apps/argus` created, migration 0001 applied, login/signup, create company "Lovixa", RLS | Second user cannot read Lovixa's rows (negative test) |
| 2 | Meta connection | OAuth round-trip, encrypted token, own pages listed as sources, Ad Library query source | `/c/lovixa/sources` shows the Lovixa page + an ad query |
| 3 | Objective | AI proposal card, confirm/edit, stored as `proposed`→`confirmed` | Reload shows the confirmed objective; nothing collected yet |
| 4 | Collect + filter | Cron runner, Graph + Ad Library fetchers, raw_items, Gemini filter → signals | One run: `items_seen > 0`, `items_kept < items_seen`, each signal has a reason |
| 5 | Report | Weekly report with evidence map + critic | A report where every number links to a signal; a planted wrong number fails the critic |
| 6 | Public pages | Submit Meta App Review for Page Public Content Access with the screencast from phase 4; on approval flip `pending_review` sources to `active` | Competitor page items appear in `raw_items` |

Phases 1–5 are each a few days. Phase 6 waits on Meta (typically 1–4 weeks) and runs in parallel from phase 4.

## Verification (end to end)

1. `npm run type-check`, `npx vitest run` (unit: crypto round-trip, objective/filter/report zod schemas with
   fixture LLM responses, critic rejects a mismatched number).
2. Local: `npm run dev` (port 3050, main session only), sign up, create Lovixa, connect the Lovixa page,
   confirm the proposed objective, hit `POST /api/jobs/run` with the cron secret, see signals and a report.
3. RLS: a second account sees no companies, sources, or reports (query via Supabase client).
4. Meta: Graph calls succeed with the stored token; rate-limit path exercised with a mocked 32 error.
